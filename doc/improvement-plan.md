# 2026-10-28 · 可用性改进计划

本轮只实现已经确认的三个高优先级项目：安装与启动、未保存保护与恢复草稿、只读实时预览。六种图元、命令语法、失败原子性及 IO 后的历史屏障继续遵循 Phase 1；SVG 兼容性扩展和插件化留待后续。

| 项目 | 设计决定 | 验收 |
| --- | --- | --- |
| 安装启动 | 发布含已编译代码的 npm tarball；提供 svg-editor、--help、--version；源码启动不重复编译 | 在临时目录安装 tarball，仅安装运行依赖，验证命令入口与脚本回放 |
| 未保存保护 | 会话记录保存基线；交互 init/read/exit 经过明确确认；Ctrl+D/Ctrl+C 保留草稿；普通 stdin 回放不询问 | 验证取消不改变文档或历史、失败保存保持未保存状态、undo 回到基线变为已保存 |
| 恢复草稿 | 通过独立端口在每个成功修改后原子更新会话草稿；--recover 显式恢复；成功保存或明确放弃时清理本会话草稿 | 验证异常中断、重新启动、多个会话草稿、损坏草稿及写入失败 |
| 实时预览 | --preview 启动仅绑定 127.0.0.1 的只读 HTTP 服务，随机访问路径；从内存生成 SVG | 验证修改自动刷新、无文档状态、停止清理、不能通过 HTTP 修改文档、预览不改变历史 |
| 文档 | 同步组件关系图、核心类图、交互时序图、模块职责、变化点、自查、操作手册和质量记录 | 图源和导出图齐备，文档说明与实际行为及测试一致 |

实现继续使用 TypeScript 和一类一文件。终端、恢复文件和 HTTP 均在 IO 适配层实现；应用层只依赖端口。预览页面随程序打包，不依赖外部资源。默认草稿目录为工作目录中的 .svg-editor/recovery，可用 --recovery-dir 指定。

分步推进：先安装入口，再会话保护与恢复，再实时预览，最后整体验证与图文同步。现有 demo.svg 属用户文件，不修改、不打包、不提交。
